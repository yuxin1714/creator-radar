审计日期：2026-09-08。基准为 CREATOR_RADAR_V1_SPEC.md 的页面职责、核心路径和 UI 原则，以及用户后续明确的 Skill、版本保留、本地优先要求。文档中的早期“仅骨架”授权记录视为历史，不拿来缩减本轮检查范围。

结论：此前“主链路能运行”被过度等同于“已符合设计”，这个判断不准确。今日情报只是过滤后的素材列表，多个页面也有职责、状态和交互缺口。本轮已修复下列可确定的本地问题；仍不完整的功能单独列出，不宣称全量 P0 验收完成。

## 已发现并修复

| 问题 | 设计或合理性判断 | 本轮修复 |
| --- | --- | --- |
| 今日情报与情报流复用同一张长列表 | 明确违反 /today 精选 Top 3–5、/feed 主动发现的职责区分 | 独立今日简报接口和卡片布局；仅通过分析与引用核验的候选可进入前五，不足不凑数 |
| 当天导入的历史作品看起来像当天内容 | 收录日期不等于发布日期，原逻辑会误导 | 两种日期分别展示；今日候选明确为近 7 天收录，不宣称今天发布 |
| 情报流没有主动探索工具，批量收录同时间时按 UUID 排列 | 缺少筛选；随机 ID 顺序不能解释为内容时间顺序 | 增加关键词、创作者、分析状态、发布时间、排序；默认发布新到旧，未知发布时间排后 |
| 创作空间新建表单优先，缺少明显的继续编辑入口 | 违反“继续创作优先” | 最近项目列表放首位，新建表单折叠；增加搜索、语言筛选和继续创作 |
| 创作列表把非成功 JSON 当数组，失败时可能崩溃或误显示为空 | 加载、空态与失败必须区分 | 检查状态码与数组类型，显示错误及重新读取按钮；创作者列表区分加载失败与零记录 |
| 全局添加只支持作品 | 与统一添加入口不符 | 增加作品/创作者类型选择，共用主页表单；完整抖音主页可识别并保留粘贴内容；短链仍可显式选择类型 |
| 设置页只有技术说明和 Skill，缺少基础偏好 | /settings 应提供可用偏好 | 新增默认创作语言/目标平台，仅应用到新项目；现有项目不被批量改写 |
| 草稿多窗口保存会静默覆盖 | 有版本历史不等于避免覆盖 | 当前编辑器提交更新时间，过期保存返回冲突，保留编辑器内容并提示导出/合并 |
| 短于 10 秒的抖音视频可能显示成几千秒，长 TikTok 视频又可能被除以千 | 单位不能按数值大小猜测 | 按平台确定单位。仅修正后续解析，不凭猜测批量改写历史元数据 |
| 作品库把资源阶段混在一起或不显示 | 元数据就绪不等于转写/分析完成 | 列表显示采集、转写、分析的实际阶段；完成分析不等于证据核验通过 |
| 长标题撑破作品库网格，桌面和手机都有横向溢出 | 不是正常的紧凑列表设计 | 限制网格最小宽度、标题换行，窄屏保留平台、作者与管理入口 |
| YouTube 页面声称“可以检查字幕”但没有可执行入口 | 不应暗示未接通能力可用 | 明确标记字幕尚未接通，不自动发请求；未把标签改名当成接入已完成 |
| 转写启动依赖整页刷新，临时读取失败缺少重试入口 | 会打断操作，错误恢复不完整 | 改为局部重新轮询，转写/分析状态提供重新读取 |
| Skill 同步说明称“历史项目保留原版本” | 实际固定的是生成记录，后续生成会重新解析版本 | 文案改为后续生成使用新版本、旧生成记录保留当时版本；选定的旧方向继续沿用快照 |
| 接口欠费或认证失败仍可能按日自动重试 | 规格要求预算不足/认证失败停止并提示 | 新失败进入 BLOCKED，调度跳过，恢复后需手动检查；不改已有订阅开关 |
| 旧 WorkDetail 和重复已完成分支残留 | 容易修错文件/分支，增加设计回归风险 | 删除未使用的详情实现及不可达重复分支 |

## 合理保留，不按本轮缺陷处理

- 服务器购买、团队账户、公网部署：用户已明确暂缓。
- TikHub 付费与上游稳定性、YouTube 字幕真实获取：本轮不新调付费接口、不绕过权限限制。
- TikTok/Instagram/X/抖音/小红书是创作输出平台选择；素材导入目前只支持抖音/TikTok/YouTube，两者范围不相同，应分别说明。
- 缺少足够分析时今日精选为空是正确状态，不需要伪造推荐。当前真实候选没有通过引用核验的分析，页面显示待研究素材。
- 原稿只在用户明确采用并保存后替换；归档不删除资产；单本机使用暂无团队登录，与用户当前目标一致。
- Mac 实机恢复、生产迁移与异地备份自动化保留后续验收，本轮只在现有 Windows 环境验证。
