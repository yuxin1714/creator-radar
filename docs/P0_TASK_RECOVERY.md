# 本地后台任务可靠性

当前架构为单个 API 进程内的 BackgroundTasks。启动时通过 PostgreSQL 会话级 advisory lock 防止两个工作台 API 同时运行；第二个进程启动失败，不能修改第一个进程的任务状态。此机制不等于持久化消息队列，也不支持多 worker 部署。

成功取得运行锁后，将遗留的转写/分析/创作 PENDING、PROCESSING，以及元数据 RUNNING、PROCESSING 标记为 FAILED，并注明服务重启中断。保留已有结果、逐字稿和正文，不自动重跑计费请求。尚未开始的元数据 PENDING 不受影响。用户从任务中心进入对应作品或项目重新发起。

元数据、转写、分析 worker 增加行锁和状态检查，避免重复请求并行执行。分析入口拒绝正在运行的重复任务，转写创建与元数据重试也串行化。

验证：34 项后端测试通过，覆盖中断恢复、保留旧结果、保留等待采集任务、恢复幂等和重复执行保护；真实 PostgreSQL 验证 API 健康检查正常、第二个运行锁被拒绝。未故意终止用户真实模型任务进行破坏式验收。

限制：数据库连接中断后的锁存活监测、跨进程持久化队列、任务自动续跑仍未实现；未来引入 worker 队列时应替换此本地保护，不可直接增加 uvicorn workers。
