# 本地持久化后台任务

2026-09-09：采集、转写、旧分析接口、译稿/多语分析和创作生成改为 PostgreSQL 事务队列 + Redis + Celery 独立进程。桌面入口自动检查并启动后台进程，任务中心显示就绪状态和排队数量。关闭浏览器不会取消任务；关机后不继续运行。

## 恢复规则

- 请求状态与队列记录同一事务提交。Redis 暂不可用时请求保留，每 3 秒尝试投递；未开始但消息丢失的任务在约 60 秒后可重新投递。
- 固定任务类型、目标 ID 和尝试编号；重复消息、旧尝试消息不重复调用供应商。新重试不能抢在上一轮收尾完成之前开始。
- API 重启不改动独立 worker 的任务状态。worker 重启保留未开始的任务；已进入处理且意外中断的任务标记失败，要求手动重试，保留原文、正文及已有结果。
- 单本机 worker 使用 solo 模式和 PostgreSQL 独占锁；并发度为 1，避免本地 GPU 和模型请求过载。后台忙于长任务时仍独立上报心跳。
- 创作者每日监控与远程 Skill 更新仍由 API 进程调度；这是本地运行方案，不是团队生产部署或付费任务的恰好一次结算保证。

## 验证

- 后端 70 项测试通过，覆盖事务回滚、重复消息、旧尝试、断开 broker、丢失投递、两种重启行为及收尾竞争。
- Windows 真实 Redis/Celery：后台停机时提交诊断任务；重启 API 和 worker 后任务完成，attempt 保持 1。诊断不调用 GPT/ASR，也不创建假作品或草稿。
- 第二个 worker 实际启动被拒绝；主 worker 保持运行。任务中心就绪/故障状态经浏览器验证。
- 前端类型检查及生产构建通过。
- 更改前数据库备份：`data/backups/backup-20260908T163314Z-75bbda18`。

日志在 `data/logs/worker-out.log`、`worker-error.log`。手动启动（先进入 `apps/api` 并激活虚拟环境）：

```sh
python -m celery -A app.worker:celery_app worker --pool=solo --concurrency=1 --loglevel=warning
```

尚未验证 Windows/Mac 跨设备恢复、生产规模、数据库服务本身的故障切换。数据库连接中断后应重启本地服务并检查任务状态，不自动重新执行状态不明的付费请求。
