# 草稿冲突对照

2026-09-09：多窗口保存冲突后不要求用户先复制正文再整页刷新，而是在编辑器中展示版本对照。

- 当前正文、标题、想法及创作配置不被轮询或冲突响应覆盖。
- 读取最新保存版本；不同的标题、想法、语言、平台、类型、方向、风格、Skill 可逐项选择。正文并排阅读，可手动整理合并。
- 确认只将结果放回编辑器，并更新保存基准时间；用户再次保存才写入数据库。其间若另一窗口又更新，会再次阻止覆盖。
- 暂存草稿记录基准版本；恢复旧版本或无法确定基准的历史暂存时同样先对照，不能通过刷新绕过冲突保护。
- 只改创作配置也更新项目版本号；最新项目已归档时必须恢复为草稿后保存。

验收：后端 71 项测试通过，包括配置变更后的旧版本写入拒绝；浏览器模拟通过本地内容保留、字段选择、手动正文合并、明确保存、旧暂存对照和 390px 布局。前端类型检查和生产构建通过。未自动合并观点或判断哪个版本质量更好。

当前工作台的保存均携带基准时间。为兼容旧直接 API 调用，未携带 expected_updated_at 的请求仍保留旧行为；这是个人本地应用边界，团队上线前应收紧接口契约。
