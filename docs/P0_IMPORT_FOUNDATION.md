# P0 第二轮：单条作品确认导入基础

日期：2026-09-01

## 已完成

- 支持抖音、TikTok、YouTube 的规范作品地址；白名单短链接最多跟随 5 次重定向。
- 只允许 HTTPS、官方精确域名、默认端口和公网解析地址，拒绝凭证、内网地址及跨平台异常跳转。
- 链接验证会确认平台网页有响应。该结果只说明地址和作品标识已确认，不代表已取得标题、作者、媒体或可长期访问。
- 用户点击“确认导入作品库”后，后端再次访问平台核对，避免信任浏览器伪造的验证字段。
- PostgreSQL 保存 Work，并创建 `WAITING_PROVIDER / PENDING` Task；相同用户、平台和作品 ID 重复导入不会重复创建。
- 作品库和任务中心显示真实记录，没有 Provider 时不显示虚假进度。

## 本轮真实验证

- 抖音短链接 `https://v.douyin.com/CUPJ7rnWTB4/` 成功展开为作品 `7680362675435605254`。
- 数据库中保存 1 条对应作品和 1 条等待任务；再次导入返回已有记录。
- Python `unittest` 5 组通过；前端 TypeScript 检查和 Next.js 生产构建通过。
- Edge 自动化通过：短链接展开、重复导入、作品库、任务中心、390px 手机布局及无页面 JavaScript 错误。

## 明确未完成

- 没有采集作品标题、作者、封面、媒体、字幕或指标。
- 没有 TikHub、Apify 或其他 Provider；任务会保持等待状态。
- 没有 Celery 业务任务、失败重试、进度流水线或详情页。
- 没有账户、多用户隔离和数据库迁移版本管理；当前为单机 `local-user`，启动时 `create_all`。
- 平台反爬、登录要求、地区限制或网络故障仍可能使响应检查失败。

下一步应先接入一个明确的作品元数据 Provider 与失败状态机，再把等待任务变成可执行任务；不应在 Provider 未确定时伪造采集结果。
